# Approved-data GitHub Pages publisher (staged; no live data published)
This feature intentionally uses a separate branch until validated and merged. The public repository and GitHub Pages are publicly readable. There is **no real authentication** on GitHub Pages; the local Node login does not protect static data.
## Allowed data
Only capturedAt, engineer name, project, six status counts, and ticket key/owner/project/status/updated are output. Ticket URLs are generated by the existing frontend and Jira enforces its own SSO. Summary, descriptions, emails, tokens and raw Jira responses are excluded.
## Validation and rollout
1. Pull the feature branch; run `node --test lenovo-qa-analytics/scripts/sanitize-public-report.test.mjs`.
2. Confirm the source schema in `%LOCALAPPDATA%\LenovoQAStatusAgent\qa-dashboard-report.json` matches the sanitizer; any unexpected shape must fail closed.
3. Execute `.\scripts\prepare-public-report.ps1` inside `lenovo-qa-analytics`. This writes a **local** sanitized file but does NOT push anything.
4. Inspect the exact file `public/data/approved-report.json` for permitted fields and check ticket counts against the original source. Confirm no private data and verify freshness.
5. Test `npm run build` and GitHub Pages behavior using a synthetic fixture only.
6. After approval, merge the branch. Explicitly set `$env:QA_PUBLICATION_APPROVED='YES'` and run `.\scripts\publish-approved-pages.ps1 -Publish` on `main`; it commits only the sanitized report. The first real publication is irreversible from a confidentiality standpoint, even if later removed.
7. Only after a successful manual publication, install the 06:15, 12:15, 18:15 tasks using `.\scripts\install-pages-publish-tasks.ps1 -EnablePublication`. The 15-minute delay allows the agent's 06:00/12:00/18:00 task to finish. A stale report (>90 min) blocks publishing. Windows must be awake, Jira SSO valid, and Git authentication available to the task account.
8. If report generation fails, the last deployed snapshot remains. Monitor the visible capturedAt timestamp; GitHub Pages does not independently poll Jira.
## Notes
The local private dashboard continues using `/api/report`; on github.io the frontend fetches `/lenovo-qa-analytics-dashboard/data/approved-report.json`. Until publication it shows an unavailable message, never sample data.
